## Design requirements
- Build an app-view/mobile-first experience first at 375–430px, with no horizontal overflow and tap targets at least 44px tall.
- Make the three pages clearly distinct:
  - Get Social: energetic Miami social/community feel; Instagram-first CTA.
  - GIV: clean wellness/clinical concierge feel; service cards and booking CTA.
  - Glamquest: editorial K-beauty/beauty feel; melanin-skin positioning, product/shop CTA.
- Prefer real official source imagery only if it can be safely referenced from the supplied sites; otherwise use tasteful gradients, shapes, and typography rather than fabricated logos or stock photos.
- Do not expose internal implementation terms, “demo” language, fake phone numbers, fake emails, or placeholder `#` links in the rendered pages.
- Include accessible descriptive link labels, visible source/website links, and a small `Powered by The Card Bar` footer consistent with the product.
- Reuse shared primitives where sensible, but do not force one generic template if that makes the brands look identical.

## Implementation guidance
- Extend `LandingPageData` only if needed; avoid breaking existing template consumers.
- Prefer a static slug registry/fallback in `src/app/p/[slug]/page.tsx` or a dedicated module. Database pages must remain first priority when a published row exists.
- Use server components unless interaction truly requires a client component.
- For any new custom templates, register them cleanly and type them.
- Add tests or a lightweight source/route test proving all three slugs, official URLs, and no placeholder hrefs are present.
